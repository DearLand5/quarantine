# Тополиная, 14 — карантин

Мобильный 3D survival horror для браузера (HTML + CSS + JavaScript, Three.js).
Ночь в многоэтажке, закрытой на карантин без объяснений. Игрок исследует свою квартиру и этаж, переписывается
с соседями в домовом чате, встречает их вживую и принимает решения, о которых соседи помнят.

Это **вертикальный срез**: первая глава с одним этажом, несколькими жильцами, телефоном и одним ключевым выбором.
Архитектура рассчитана на расширение до полноценной сюжетной игры.

## Быстрый старт

Нужен любой локальный HTTP-сервер: ES-модули **не работают** при открытии `index.html` через `file://`.

```bash
# вариант 1 — встроенный сервер без зависимостей (Node.js 18+)
npm start            # или: node server.js
# откройте http://localhost:8080/

# вариант 2 — Python
python3 -m http.server 8080
```

Устанавливать пакеты не нужно: Three.js лежит в `vendor/three/` (лицензия MIT, см. `vendor/three/LICENSE`).

Проверка синтаксиса всех модулей:

```bash
npm run check        # node tools/check.mjs
```

Порт меняется переменной окружения: `PORT=3000 node server.js`.

## Запуск на смартфоне

1. Запустите `npm start` на компьютере. Сервер выведет адреса вида `http://192.168.1.23:8080/`.
2. Подключите телефон к **той же Wi‑Fi сети** и откройте этот адрес в Chrome (Android) или Safari (iOS).
3. Поверните телефон горизонтально и нажмите «Нажмите, чтобы начать». Игра попросит полноэкранный режим.
   Звук включится только после этого касания — таковы ограничения мобильных браузеров.
4. Для «приложения на экране» используйте «Добавить на главный экран»: есть `manifest.webmanifest`.

Замечания:

- HTTPS не нужен: игра не использует камеру, геолокацию и другие API, требующие защищённого соединения.
- На iPhone при включённом беззвучном режиме (переключатель сбоку) Web Audio может молчать. Выключите его.
- На iOS полноэкранный API ограничен. Добавление на главный экран даёт почти полноэкранный режим.
- Шрифты загружаются с Google Fonts. Без интернета используются системные шрифты, игра работает.

## Управление

| Действие | Сенсорный экран | Клавиатура / мышь |
|---|---|---|
| Ходьба | плавающий джойстик в левой части экрана | WASD / стрелки |
| Обзор | свайп в правой части экрана | мышь (клик по экрану — захват курсора) |
| Взаимодействие | кнопка «Действие» или короткий тап в зоне обзора | E / Пробел |
| Бег | кнопка «Бег» (переключатель или удержание — в настройках) | Shift |
| Присесть | кнопка «Присесть» | C / Ctrl |
| Фонарик | кнопка «Фонарь» | F |
| Телефон | кнопка «Телефон» (на ней счётчик непрочитанных) | Tab / Q / P |
| Сумка (инвентарь) | маленькая кнопка слева сверху | I |
| Пауза | маленькая кнопка справа сверху | Esc |
| Вариант в диалоге | тап по варианту | 1–9 |

В настройках можно изменить чувствительность камеры, инверсию оси Y, размер кнопок, раскладку для левши
и **расположение каждой кнопки** (режим перетаскивания). Раскладка хранится отдельно от сохранений.

Пока телефон открыт, мир не останавливается: можно медленно идти левым джойстиком (в горизонтальной ориентации),
сообщения приходят, NPC живут по расписанию. Полностью время останавливает только пауза.

## Архитектура

Проект собран без сборщика: нативные ES-модули и `importmap` в `index.html`. Каждая система — отдельный модуль.
Системы общаются через шину событий и единое состояние, а не напрямую.

### Ключевые принципы

- **Единый источник состояния.** `GameState.data` — простой JSON: время, флаги, инвентарь, двери, свет, память NPC,
  переписки (включая **незавершённые** цепочки сообщений), звонки, галерея, задания, улики. Сохранение — это
  сериализация этого объекта. Объекты Three.js и функции в нём не хранятся, только идентификаторы.
- **Данные отдельно от логики.** Сюжет, переписки, диалоги, расписания и планировка этажа описаны в `src/data/`.
  Данные обращаются к миру только через фасад `StoryContext`.
- **Шина событий** (`EventBus`): `chat:message`, `door:changed`, `npc:arrived`, `sound:play`, `hud:toast` и т.д.
  Каждая подписка возвращает функцию отписки.
- **Единый игровой цикл** в `Game.js`: `dt` ограничен сверху, второстепенные системы обновляются реже
  (расписания NPC — раз в 0,3 с, пул света — раз в 0,15 с, сюжетные события — раз в 0,5 с).

### Модули

**core/**
- `EventBus` — подписка, отписка, однократные события. Ошибка в обработчике не ломает остальных подписчиков.
- `GameState` — сериализуемое состояние мира и `deepMerge` при загрузке (новые поля получают значения по умолчанию).
- `SceneManager` — рендерер, сцена, камера, профили качества (low/medium/high/auto), адаптивное разрешение по
  среднему FPS. Здесь же «съёмка камерой телефона»: рендер в отдельную цель с включённым **слоем аномалий**
  (`LAYER_ANOMALY`) — то, что видно только на фотографиях, — и мобильная обработка снимка (шум, экспозиция, виньетка).
- `AssetManager` — процедурные текстуры (canvas), общая библиотека материалов, таблички с текстом, загрузка GLB
  с кэшем и запасным вариантом. Подмена ресурсов файлами — через `assets/manifest.json`.

**world/**
- `WorldBuilder` — собирает этаж из `locations.js` и `furnishing.js`: стены с проёмами и панелями
  («масляная краска снизу, побелка сверху»), откосы, плинтусы, окна, двери, мебель, светильники, коллайдеры.
- `StaticBatcher` — объединяет статическую геометрию по паре «комната + материал». Сотни деталей превращаются
  в десятки вызовов отрисовки, а разбиение по комнатам сохраняет отсечение по пирамиде видимости.
- `RoomManager` — определяет текущую комнату и скрывает геометрию квартир за закрытыми дверями
  (упрощённое портальное отсечение).
- `PhysicsSystem` — 2D-столкновения круга с AABB-прямоугольниками на плоскости XZ, с разбиением шага, чтобы
  на низком FPS не проходить сквозь стены. Динамические коллайдеры: двери и NPC. Проверка «через стену» для
  взаимодействий и свидетелей.
- `LightingSystem` — **фиксированный пул** точечных источников, который переезжает к ближайшим включённым
  светильникам. Число источников не меняется, поэтому шейдеры не перекомпилируются. Цепи питания (квартира,
  коридор, соседи, аварийная), выключатели, мерцание, сюжетные сбои, фонарик игрока.
- `Door` — полотно на петлях с плавной анимацией, цепочкой, глазком, номером, пломбой.
- `Exterior` — вид из окон: двор с оцеплением, палатки, машины с мигалками, прожекторы, соседние дома с окнами,
  которые гаснут и загораются. Без освещения и тумана, почти бесплатно для GPU.
- `InteractionSystem` — луч из центра экрана, подсказка, проверка препятствий, действия с удержанием.
- `TextureFactory`, `Props`, `geometry` — процедурные текстуры, каталог мебели, геометрия с UV в метрах.

**player/**
- `InputManager` — единое состояние ввода для клавиатуры, мыши (pointer lock) и сенсорного управления.
- `MobileControls` — Pointer Events с отслеживанием `pointerId`: одновременно работают джойстик, обзор и кнопки.
  Есть редактор раскладки, размер кнопок, режим для левшей и короткий тап для взаимодействия.
- `PlayerController` — ускорение и торможение, бег с выносливостью, плавное приседание, шаги по типу поверхности,
  покачивание камеры.
- `CameraController` — углы обзора, встряска, FOV при беге, режимы «глазок» и «фокус на собеседнике».
- `ViewModel` — руки от первого лица: фонарик, телефон, анимация «тянуться к предмету».

**npc/**
- `HumanoidModel` — процедурная модель человека с иерархией суставов: ходьба, дыхание, жесты при разговоре,
  поворот головы к игроку, курение, «прислушивается к двери». `GltfHumanoid` — адаптер для GLB со скелетом
  (клипы `idle` / `walk` / `talk`) с тем же интерфейсом.
- `NPCController` — движение по графу, открывание дверей на пути и закрывание за собой, видимость «за дверью»,
  ожидание, если игрок стоит на пути, коллайдер и зона взаимодействия.
- `NPCSchedule` — навигационный граф (A*) и правила расписаний (первое подходящее правило решает, где персонаж).
- `NPCManager` — создание жильцов, обновление расписаний, ответ на стук и разговор в дверях
  (с цепочкой или без), аномальная фигура, проверка «видит ли NPC точку».
- `DialogueSystem` — граф реплик с условиями и последствиями, отметка уже выбранных вариантов.
- `RelationshipSystem` — память персонажей: доверие, уважение, страх и подозрительность к игроку; известные факты,
  убеждения (могут быть ошибочными), обещания (открыто / выполнено / нарушено), увиденные события, утверждения,
  отношения с другими жильцами, история взаимодействий.

**phone/**
- `PhoneController` — оболочка смартфона: экран блокировки, домашний экран, приложения, статус-бар (время,
  сигнал, батарея), разрядка и зарядка, звонки, внутренние баннеры, эффект помех.
- `Messenger` — UI мессенджера «Дворик»: список чатов, лента с ответами на реплики, удалёнными и исправленными
  сообщениями, фото, голосовыми, индикатором «печатает…», разделителем непрочитанного, вариантами ответа,
  свободным вводом и прикреплением фото из галереи.
- `ChatManager` — логика переписок. Сюжетные цепочки с паузами, временем набора (пожилые печатают медленнее),
  опечатками, исправлениями и удалением. Выборы с тайм-аутами, бытовые разговоры, которые звучат один раз, ответы на
  свободный ввод, реакции на отправленные фото по тегам снимка. Доставка зависит от сигнала: без сети исходящие ждут
  с часиками, входящие задерживаются. Все незавершённые цепочки сериализуются.
- `IntentRecognizer` — распознавание намерений по корням слов и упоминаний жильцов по имени. Честно возвращает
  `unknown`, если не уверен.
- `ContactManager` — входящие и исходящие звонки, пропущенные вызовы, голосовые сообщения после пропущенного,
  обрыв связи.
- `Gallery` — снимки камеры (хранятся отдельно) и полученные фото. Просмотрщик: масштаб щипком и колёсиком,
  панорамирование, двойной тап, отправка в чат.
- `PhotoFactory` — процедурные «фотографии» и кадры камеры наблюдения. Кадры рендерятся из настоящей 3D-сцены,
  поэтому их можно сверять с тем, что игрок видит в мире.
- `NotificationManager` — баннеры поверх мира и внутри телефона, звуки и вибрация, список на экране блокировки.

**story/**
- `StoryContext` — фасад для данных сценария: флаги, инвентарь, переписки, улики, отношения, мир.
- `StoryManager` — сценарные действия, затрагивающие несколько систем: отключение света, стук в дверь,
  глазок, записка под дверью, теги для фотографий и т.д.
- `QuestManager` — задания и цели; показываются в «Заметках» телефона.
- `EventManager` — сюжетные события «условие → действие», каждое срабатывает один раз; момент срабатывания
  сохраняется.
- `EndingManager` — подсчёт итогов главы по флагам и отношениям.
- `Interactions` — обработчики взаимодействий с предметами, дверями и NPC.

**systems/**
- `Inventory` — предметы, улики, передача NPC.
- `AudioManager` — Web Audio: шины громкости, PannerNode (HRTF, на низком качестве equal-power), реверберация
  по типу помещения и приглушение звуков за стенами (фильтр низких частот, если между слушателем и источником стена).
  Контекст создаётся после жеста пользователя. Есть подмена звуков файлами.
- `SoundSynth` — процедурный синтез всех звуков: шаги по разным поверхностям, скрип дверей, замки, цепочка, стук,
  лифт, трубы, неразборчивая речь, шёпот, сирена, вертолёт, уведомления, вибрация, рингтон, музыкальные акценты.
- `Ambience` — фоновые петли по комнатам (вентиляция, холодильник, часы, телевизор за стеной, ветер) и редкие
  случайные события с текстовыми субтитрами звуков.
- `SaveManager` — автосохранение и 3 ручных слота, версия формата, цепочка миграций, обработка переполнения хранилища.
- `SettingsManager` — настройки игрока, определение профиля качества для режима «авто».

**ui/**
- `HUD` — прицел, подсказка, удержание, цель задания, фонарик, баннеры, субтитры, тосты, затемнение, глазок,
  видоискатель камеры.
- `MenuManager` — главное меню, пауза, слоты сохранений, настройки с вкладками, управление, «Об игре»,
  экран итогов главы, подтверждения.
- `DialogueUI`, `InventoryUI`, `Reader` — диалоги с эффектом печати, сумка, чтение записок и документов.

**data/**
- `characters` — жильцы и контакты: биография, секрет, страх, голос, внешность, расписание, начальное доверие.
- `messages` — история чатов до начала игры, сюжетные цепочки, бытовые разговоры, ответы на свободный ввод,
  маршрутизация ответов в группе, реакции на фото.
- `dialogues` — разговоры вживую и ответы на стук.
- `locations` — комнаты, проёмы, двери, окна, светильники, навигационный граф.
- `furnishing` — расстановка мебели и интерактивных зон.
- `storyEvents`, `quests`, `items` (предметы и улики), `calls` (сценарии звонков).

## Добавление ресурсов

Все текстуры, модели людей и звуки сейчас **процедурные**. Любой ресурс можно заменить файлом, не трогая код:
положите файл в нужную папку `assets/` и пропишите его в `assets/manifest.json`.

```json
{
  "textures": { "wallpaper_room": "my_wallpaper.jpg", "floor_corridor": "tiles.jpg" },
  "models":   { "zinaida": "zinaida.glb", "gennady": "gennady.glb" },
  "audio":    { "door_open": "door_creak.ogg", "vent": "vent_loop.ogg" }
}
```

**Текстуры** (`assets/textures/`). Ключи — имена из `TEXTURE_DEFS` в `src/core/AssetManager.js`:
`wallpaper_room`, `wallpaper_hall`, `wallpaper_zina`, `paint_green`, `whitewash`, `concrete`, `tiles_white`,
`floor_corridor`, `parquet`, `door_leather` и другие. Там же задан размер тайла в метрах: UV-координаты статической
геометрии считаются в метрах, поэтому текстура не растягивается. Используйте бесшовные изображения (512–1024 px).
Параметры материалов (шероховатость, металличность, рельеф) задаются в `MATERIAL_DEFS`.

**Модели персонажей** (`assets/models/`). Ключ — id персонажа (`zinaida`, `marina`, `denis`, `gennady`).
GLB масштабируется по росту из `look.height`. Если в файле есть анимационные клипы `idle`, `walk`, `talk`
(регистр не важен), они переключаются автоматически (`GltfHumanoid`). Если файл не загрузился, остаётся
процедурная модель, а ошибка пишется в консоль.

**Мебель и предметы.** Каталог — `src/world/Props.js`: каждая функция собирает предмет и возвращает коллайдеры
и зоны взаимодействия. Чтобы заменить предмет моделью, загрузите GLB через `assets.loadModel()` и добавьте
сцену в группу предмета. Коллайдеры остаются прежними.

**Звуки** (`assets/audio/`). Ключи — имена в `SYNTHS` (одноразовые) и `LOOPS` (зацикленные) из
`src/systems/SoundSynth.js`: `footstep`, `door_open`, `door_close`, `knock`, `lock`, `chain`, `notify`, `vibrate`,
`elevator`, `pipes`, `babble`, `sting`, `vent`, `fridge`, `clock`, `tv`, `wind` и другие.
Файл декодируется после первого касания экрана; при ошибке используется синтез.
Шаги сейчас синтезируются с учётом поверхности: файл заменит звук для всех поверхностей.

**Шрифты** (`assets/fonts/`). Чтобы игра работала полностью офлайн, положите файлы `.woff2` и замените `<link>`
на Google Fonts в `index.html` своим `@font-face` в `styles/main.css`.

## Сохранения

- `localStorage`, ключи `topolinaya14.save.auto`, `topolinaya14.save.slot1…3`. В каждом слоте —
  `{ meta, data }`, где `data` — полный `GameState.data`.
- Снимки камеры хранятся отдельно (`topolinaya14.photo.<id>`), чтобы не дублироваться в каждом слоте.
  Полученные процедурные фото и кадры камер не хранятся, а генерируются заново.
- Настройки — `topolinaya14.settings`, отдельно от прогресса.
- Формат версионирован: `SAVE_VERSION` в `src/core/GameState.js`, цепочка `MIGRATIONS` в
  `src/systems/SaveManager.js`. Сохранение из более новой версии игры не загрузится, а покажет понятную ошибку.
- Переполнение хранилища (`QuotaExceededError`) и повреждённые сохранения обрабатываются и показываются игроку.
- Восстанавливаются: позиция и взгляд игрока, инвентарь, двери и пломбы, питание и сломанные лампы,
  позиции и активности NPC, память и отношения, все переписки со статусами, незавершённые цепочки сообщений,
  ожидающие выборы, звонки, уведомления, галерея, флаги, задания, улики, сработавшие события.

## Производительность

| Профиль | Макс. pixel ratio | Источников света в пуле | Тени | Материалы | Текстуры |
|---|---|---|---|---|---|
| low | 1.0 | 3 | нет | Lambert | 256 px |
| medium | 1.5 | 4 | нет | Standard (PBR) | 512 px |
| high | 2.0 | 6 | только от фонарика | Standard (PBR) | 512 px |

Режим «авто» выбирает профиль по `deviceMemory`, `hardwareConcurrency` и типу устройства.

Что ещё сделано для мобильных устройств:

- **Адаптивное разрешение**: каждые 2 с по среднему FPS масштаб рендера снижается (до 55–70 %, зависит от профиля)
  или восстанавливается. Дополнительно есть ручной множитель разрешения.
- **Объединение статической геометрии** по комнатам и материалам (`StaticBatcher`).
- **Инстансинг** повторяющихся объектов (запасы воды Лапина — `InstancedMesh`).
- **Упрощённое портальное отсечение**: квартиры за закрытыми дверями не рисуются (`RoomManager`).
- **Фиксированный пул света** без перекомпиляции шейдеров. Внешний мир нарисован без освещения.
- **Переиспользование** геометрии (кэш по размерам) и материалов (общая библиотека).
- **Пониженная частота** второстепенных систем: расписания NPC, назначение света, проверки событий,
  поиск объекта под прицелом.
- Аудио на низком профиле использует equal-power вместо HRTF.

Одинаковая производительность на всех телефонах не гарантируется. На слабых устройствах выберите профиль «low»
и уменьшите разрешение в настройках.

## Известные ограничения

Честный список того, что сделано упрощённо или пока не сделано:

- **Все модели, текстуры и звуки — процедурные заготовки.** Люди собраны из примитивов с процедурной анимацией,
  без скелета и мимики (адаптер для GLB есть, но готовых моделей в комплекте нет). Текстуры нарисованы на canvas,
  звуки синтезированы. Визуально это стилизованный, а не фотореалистичный прототип.
- **Один этаж**: квартира игрока, квартира Зинаиды Павловны (в неё можно зайти по приглашению), три прихожие
  соседей, видимые из дверей, коридор, лифтовый холл и лестничная площадка. Лестницы вверх и вниз закрыты по сюжету
  (решётка и щит штаба), лифт не работает.
- **Только первая глава** с тремя исходами и подсчётом последствий. Это итоги главы, а не полноценные концовки
  игры. Задел на следующие главы есть (пропуск «П/я 17», ключ, флаги), но сами главы не написаны.
- **Свободный ввод в чате — без языковой модели**: распознавание намерений по ключевым корням слов и упоминаниям
  имён. Персонаж отвечает по теме, но не понимает сложные фразы. В интерфейсе об этом есть пометка.
  Основные сюжетные развилки идут через варианты ответа.
- **Голосов нет**: NPC «говорят» синтезированным неразборчивым бормотанием с субтитрами, озвучки нет.
- **Только русский язык**: выбор языка в настройках есть, но других локализаций нет.
- **Физика двумерная** (плоский этаж, круг против прямоугольников). Предметы нельзя толкать или брать в руки
  физически.
- **Тестирование** проводилось в Chromium (headless) с эмуляцией мобильного экрана и сенсорного ввода.
  На реальных устройствах iOS и Android игра не проверялась: возможны особенности с полноэкранным режимом,
  звуком и производительностью.
- **Смена профиля качества** (освещение, тип материалов) применяется после перезагрузки страницы. Разрешение
  меняется сразу.
- **Глазок** — широкий угол обзора с круглой маской, а не настоящее искажение «рыбий глаз».
- **Тени** — только от фонарика и только на профиле high. Отражений в зеркалах нет.
- Время в игре идёт примерно в 10 раз быстрее реального. Ночь первой главы (21:40 → ~00:30) занимает около 17–25 минут реального времени; кровать дома позволяет пропустить 15 игровых минут.
